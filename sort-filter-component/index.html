Notes

Sort options are fixed in code There is no editor picker. Every option is pre-directioned, so the user gets no ascending / descending control.
    Loan Features are fixed in code Three features. The data source for each is still an open question on CMS-1903.
      Category is navigation, not a filter The existing category tab strip moves into this panel unchanged. Each option loads a page that already exists, so it does not combine with the filters.
        Provider options are derived Read from the product list in ProductMetaConfig. Adding a product adds its provider automatically — nothing to maintain here.

        Notes for reviewers (EN)
        • Config depth is deliberately toggles only: enable the panel, pick the default sort, show or hide each group. The fixed lists are reference notes, not editable fields.
        • Category is navigation. Its options are links to existing category pages, so they do not combine with the filters. Here the links are intercepted so you stay in the demo — the destination is named instead.
        • Provider is OR within its group; Loan Features is AND within its group; the two filter groups AND with each other.
        • Panel and table structure, class names and column order are taken from prototype-redesign.html so the non-focus components match the prototype already shared. Simplified in one way: the mobile drawer / backdrop is not rebuilt — below 1024px the panel simply stacks above the results.
        • The “Compare in detail” product cards below the table render the same filtered, sorted set in the same order — that is CMS-1903 requirement 7, and the reason sorting and filtering act on the product set rather than on either component.
        • Card tags (“Instant approval · No processing fee”) are derived from each product's own feature flags rather than written by hand, so no marketing copy is invented here.
        • Figures are illustrative and exist only to demonstrate ordering and filtering. They do not reconcile with the live page.
